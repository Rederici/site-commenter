# Site Commenter — расширение Chrome

Тонкая обёртка над `@sitecommenter/ui-comments`: content script монтирует окно
замечаний в shadow root страницы, снимок берётся нативный
(`chrome.tabs.captureVisibleTab`), а отправка создаёт задачу в YouTrack.

## Сборка

```bash
npm install
cp .env.example .env        # и задайте свои значения
npm run build:extension     # → apps/extension/dist
```

Значения по умолчанию вшиваются в бандл при сборке, поэтому `.env` нужен
именно на этапе `build:extension`:

| Переменная | Что задаёт |
|---|---|
| `SITECOMMENTER_YOUTRACK_URL` | инстанс YouTrack, куда уходят задачи |
| `SITECOMMENTER_DEFAULT_SITES` | домены по умолчанию для попапа, через запятую |

Переменные окружения важнее `.env`. Без `.env` собирается нейтральный
placeholder (`yt.example.com` / `todo.example.com`), а сборка предупреждает об
этом. Сам `.env` в репозиторий не попадает.

Затем `chrome://extensions` → включить «Режим разработчика» → «Загрузить
распакованное» → выбрать `apps/extension/dist`.

Для локального стенда добавьте `127.0.0.1` в список сайтов в popup — манифест
больше не патчится.

## Как это работает

- **content script** (`src/content.tsx`) читает маршрут и заголовок страницы,
  монтирует `UiCommentsProvider` + `UiCommentsWidget` в shadow root и
  отправляет замечание в background.
- **service worker** (`src/background.ts`) отдаёт нативный снимок вкладки,
  открывает окно по кнопке на панели Chrome и `Alt+Shift+C`, а также создаёт
  задачу в YouTrack.
- **OAuth** (`src/oauth.ts`) — Authorization Code + PKCE. Access/refresh-токены
  лежат в `chrome.storage.local`. Первый вход запускается при первой отправке.
- **YouTrack** (`src/youtrack.ts`) — находит проект, создаёт задачу, прикладывает
  снимок и открывает её в новой вкладке.
- **разметка** — тот же SVG-слой модуля, поэтому попадает на нативный снимок
  без склейки.

## Настройки (popup)

Клик по иконке расширения открывает popup:

- **Войти в YouTrack** — OAuth-авторизация;
- после входа показываются **Проект** и **Тип задачи**:
  - проекты загружаются из YouTrack API и показываются в выпадающем списке;
  - проекта по умолчанию нет — его нужно выбрать явно; пока проект не выбран,
    кнопка «Создать задачу» заблокирована;
  - типы задач берутся из проекта; если доступен `Bug`, он выбирается по умолчанию;
- **Выйти** — сбрасывает авторизацию и выбранный проект, чтобы можно было войти другим пользователем.
- **Где работает попап** — список доменов или URL, на которых content script
  вообще ставится на страницу. Сайты можно добавлять и удалять без пересборки;
  после изменения нужно обновить открытые вкладки. Начальный список задаётся
  `SITECOMMENTER_DEFAULT_SITES` при сборке.

Выбранные проект и тип хранятся в `chrome.storage.local`; окно замечания
показывает их в подсказке и использует при создании задачи. Само окно
замечания открывается кнопкой на странице или `Alt+Shift+C`.

## Текущая конфигурация

- YouTrack: `SITECOMMENTER_YOUTRACK_URL` из `.env`
- OAuth client ID: **test-sitecommenter**
- проект: **не выбран по умолчанию**, выбирается в popup
- тип: **Bug** по умолчанию, если он есть в проекте; остальные значения
  загружаются из YouTrack
- сайты: `SITECOMMENTER_DEFAULT_SITES` из `.env`, список редактируется в popup
- заголовок: обязательный, до 120 символов
- описание: необязательное, если приложен снимок

Чтобы изменить URL или список сайтов, задайте их в `.env` и пересоберите
расширение. Client ID меняется в `YOUTRACK_CLIENT_ID` в `src/youtrack-config.ts`.

## OAuth

В OAuth-клиенте YouTrack должны быть включены:

- Authorization Code flow;
- Require PKCE;
- Require user consent;
- Redirect URI `https://<extension-id>.chromiumapp.org/`.

ID расширения фиксируется полем `key` в `manifest.json`; при смене ключа
redirect URI нужно обновить в YouTrack. Публикация в Store не требуется.

Client secret для публичного PKCE-клиента не нужен. Если инстанс потребует
секрет, его нельзя безопасно хранить в расширении — понадобится небольшой
backend, который обменивает код на токен.

## Настройка под свой сервис

| Что | Где |
|---|---|
| Домены, на которых работает попап | popup → «Где работает попап» (или `.env`) |
| YouTrack URL | `.env` → `SITECOMMENTER_YOUTRACK_URL` |
| OAuth client ID | `src/youtrack-config.ts` |
| Проект и тип задачи | popup расширения |
| Горячая клавиша | `manifest.json` → `commands` |

`captureVisibleTab` требует `<all_urls>` **или** `activeTab`. В манифесте стоит
`<all_urls>` — так снимок работает из плавающей кнопки. Для минимальных прав
уберите `<all_urls>` и откройте окно кнопкой на панели Chrome или хоткеем.

## Что происходит при отправке

1. Снимок видимой области (с разметкой), заголовок и текст уходят в background.
2. Background получает OAuth-токен (при необходимости открывает окно входа).
3. Создаётся задача в выбранном проекте, тип — из настроек, `summary` = заголовок, State по умолчанию.
4. Снимок загружается вложением и вставляется в описание.
5. Query-параметры из URL добавляются в описание таблицей «Параметр / Значение»,
   полный URL сохраняется для перехода и воспроизведения.
6. Открывается вкладка с созданной задачей.

Описание можно не заполнять, если приложен снимок. Заголовок обязателен.

Задача создаётся сразу, не черновиком. Если она не нужна — удалите её в
YouTrack.

## Ограничения

- Снимается активная вкладка и только видимая область.
- `captureVisibleTab` ограничен двумя вызовами в секунду.
- Расширение не ставит второй виджет на страницах, где уже есть встроенный
  модуль (метка `data-ui-comments-inline`).
- Настройки проекта/типа пока не редактируются из UI.
